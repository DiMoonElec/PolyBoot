# Тестовое приложение PC13 для прокси-демо AT32F435VGT7

Открыть `at32f435vgt7-proxy-blink.eww` и собрать Debug в IAR EWARM.
PC13: 1 секунда высокого уровня, 1 секунда низкого, полный период 2 секунды.
Отсчёт — по прерыванию SysTick с периодом 1 мс; блокирующих задержек нет.
Кварц — 16 МГц, ядро — 200 МГц. Код тактирования и SysTick общий с демо.

## Память

- Загрузчик: `0x08000000–0x08003FFF`, 16 Кбайт.
- Приложение: `0x08004000–0x080FF7FF`, 1006 Кбайт (1030144 байта).
- Хэш исходного бинарника, 16 байт: `0x080FF7E0–0x080FF7EF`.
- MAC Poly1305: `0x080FF7F0–0x080FF7FF`.
- Настройки: `0x080FF800–0x080FFFFF`, исключены из обновления.

Linker-файл исключает последние 32 байта из размещения кода приложения.
Таблица векторов находится по адресу `0x08004000`; main устанавливает
собственный VTOR до включения SysTick. Стек — 4 Кбайт, heap — 0.

## Генерация обновления

После сборки запустить `scripts/generate.bat`. Нужен PolyBootGen с командой
`build-v2`. Без аргументов батник использует PATH; первым аргументом можно
передать полный путь к новой сборке PolyBootGen.exe. Конфигурация
`scripts/config.xml` задаёт
пакет FORMAT=2 / SINGLE, ROOT, BootloaderVersion=2 и ProxyVersion=1.
Секция слейвов в этот тестовый пакет не включена.

DeviceId — `at32f435vgt7-proxy-bootloader`. Ключи соответствуют
`../config/private_keys.inc`; при изменении ключей обновить XML.
Версии из заголовков относятся к метаданным пакета. В хвосте Flash хранится
хэш исходного бинарника, защищённый общим MAC. MinUpdaterVersion=0.0.0
не задаёт дополнительного ограничения версии утилиты.

Выходной bin: `Debug/Exe/at32f435vgt7-proxy-blink.bin`.
Файл обновления: `scripts/at32f435vgt7-proxy-blink.xbin`.
Bin без сформированных хэша/MAC не является готовым образом обновления.

## Проверка

1. Прошить прокси-загрузчик программатором и активировать его через UART8.
2. Загрузить xbin утилитой ПК. Проверить, что команда 79 возвращает
   `79 00 [HASH:16]` и хэш совпадает с рассчитанным генератором.
3. Запустить приложение: PC13 должен переключаться каждую секунду.
4. После включения питания без активации приложение должно запуститься
   через 10 секунд после начальной проверки MAC.
5. Проверить сохранность сектора настроек.

## Композитное обновление

`scripts/generate_complex.bat` собирает пакет FORMAT=2 / COMPLEX по
`scripts/complex.xml`. Как и основной батник, принимает необязательный
первый аргумент — полный путь к PolyBootGen.exe с поддержкой build-v2.

Пакет содержит две секции:

| Target | DeviceId | Версия | Область приложения |
| --- | --- | --- | --- |
| ROOT | at32f435vgt7-proxy-bootloader | Из ../firmware_version.h | 0x08004000, 1006K |
| SLAVE | at32f413cbt7-uart-bootloader | Из slave_firmware_version.h | 0x08003000, 116K |

Бинарник приложения слейва `scripts/at32f413cbt7-blink.bin` лежит рядом
со скриптом. Он переключает PC13 каждую секунду по SysTick. При замене
бинарника пересчитать его хэш и MAC новым генератором; заголовок
`slave_firmware_version.h` относится к метаданным версии пакета. Ключи секции SLAVE должны совпадать с загрузчиком
слейва. Оба загрузчика должны поддерживать команды протокола V2.

Одна секция SLAVE используется для всех слейвов с таким Device ID:
12 одинаковых секций создавать не требуется. Наличие и идентификаторы
позиций 0–11 проверяет утилита ПК через прокси мастера.

Результат: `scripts/at32f435vgt7-proxy-complex.xbin`.
Для проверки загрузить его утилитой в режиме комплексного обновления,
проверить ID/хэши слейвов, прошивку через обе группы UART, результат MAC
и мигание PC13 после выхода слейвов в приложение через аппаратный сброс.

## Совместимость хвоста образа

Новое ядро ожидает 16 байт хэша исходного бинарника и 16 байт MAC.
Генератор и утилита ПК должны поддерживать эту раскладку и 18-байтный
успешный ответ команды 79. Ранее созданные xbin с версией перед MAC
нужно пересоздать. Заголовки версий и XML в scripts относятся к метаданным
прежней конфигурации генерации; версия больше не является полем хвоста Flash.
