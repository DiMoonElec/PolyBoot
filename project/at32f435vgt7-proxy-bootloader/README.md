# Испытательное демо PolyBoot Proxy V1 для AT32F435VGT7

Открыть `at32f435vgt7-proxy-bootloader.eww` в IAR EWARM.
Это отдельный проект с `BOOTLOADER_USE_PROXY`; обычное UART-демо
и его конфигурация не изменяются.

Кварц — 16 МГц, ядро — 200 МГц. Связь с ПК: UART8, PC2 TX / PC3 RX,
115200, 8N1. Активация — командой в течение 10 секунд после проверки
образа; после активации загрузчик обслуживает обычные и прокси-команды.

## Память

Загрузчику выделены 16 Кбайт: `0x08000000–0x08003FFF`.
Приложение начинается с `0x08004000`, длина — 1006 Кбайт (1030144 байта).
Хэш исходного бинарника находится по `0x080FF7E0`, MAC — по `0x080FF7F0`.
Последний сектор `0x080FF800–0x080FFFFF` занят настройками и не обновляется.
DeviceId — `at32f435vgt7-proxy-bootloader`.

## Подключения слейвов

| ID | UART мастера | RESET | CS |
| --- | --- | --- | --- |
| 0–5 | UART7 | PA15, активный 0 | PD2–PD7 соответственно |
| 6–11 | UART5 | PE0, активный 0 | PE6–PE1 соответственно |

Все CS активны уровнем 1. На обеих шинах включён аппаратный SWAP:

| UART | Номинальные функции пинов | Фактические функции после SWAP |
| --- | --- | --- |
| UART7, MUX 8 | PB4 TX, PB3 RX | PB3 TX мастера, PB4 RX мастера |
| UART5, MUX 8 | PB6 TX, PB5 RX | PB5 TX мастера, PB6 RX мастера |

Для отладки использовать SWD: PA15, PB3 и PB4 заняты прокси,
поэтому JTAG и SWO на этих ногах использовать нельзя.

## Работа порта

A0 не опрашивает устройства. Он подготавливает обе группы:

1. Снимает все CS и устанавливает оба RESET в 0.
2. Через 2 тика SysTick переводит PB3–PB6 в выходы с уровнем 0.
3. Через следующие 2 тика снимает RESET.
4. Через 11 тиков освобождает GPIO шины, инициализирует FIFO и оба UART
   с SWAP на 115200, 8N1. Все CS остаются в 0.

SysTick имеет период 1 мс. Два тика гарантируют паузу не менее 1 мс,
11 тиков — не менее 10 мс при неизвестной фазе текущего тика.
Операция неблокирующая, ожидание проверяется из poll.

A1 всегда возвращает 12 позиций с ID 0–11. Наличие устройства,
готовность его загрузчика, Device ID и хэш проверяет утилита ПК.

A2 сначала снимает все CS и сбрасывает оба UART. После паузы 10 тиков
очищает FIFO выбранной группы, включает её UART и устанавливает нужный CS.
После ещё 10 тиков подтверждает готовность. ID вне 0–11 возвращает ошибку
и оставляет все CS неактивными. A2 поддерживает переключение без A3.

A3 снимает CS, сбрасывает UART и после 10 тиков подтверждает закрытие.
До A0 закрытие успешно сразу. Слейвы аппаратно не сбрасываются.
При выходе в приложение порт дополнительно освобождает IRQ, GPIO и clocks.

## Расположение кода

- `project/src/bootloader_proxy_port.c`: последовательности INIT/OPEN/CLOSE,
  фиксированный список позиций и выбор UART по ID.
- `project/hw_conf/src/hw_proxy_config.c`: RESET, CS, GPIO MUX, UART SWAP,
  аппаратный init/deinit.
- `project/src/proxy_serial_port.c`: два UART с IRQ и кольцевыми FIFO.
- Общий протокол: [`../../core/PROXY.md`](../../core/PROXY.md).

## Буферизация

На каждый UART слейвов выделены RX FIFO 16384 байта и TX FIFO 128 байт.
Максимальная оценка серии стирания F413: 116 событий по 10 байт payload
плюс окончательный ответ 2 байта. С учётом максимально возможного
экранирования Binex это 3377 байт. Весь поток помещается в FIFO даже
без чтения в ходе этой серии. Для другого слейва/протокола оценку пересчитать.

Аппаратная ошибка UART или переполнение FIFO фиксируются полем error
соответствующего канала в `proxy_serial_port.c`. До повторного открытия
или INIT канал не выдаёт принятые данные; ПК получает таймаут.
Общий модуль не пропускает события и не добавляет задержку перед их
пересылкой. Эти решения о скорости и буфере принадлежат проекту.

## Проверка на плате

1. Активировать мастер через UART8. До активации A0–A4 игнорируются.
2. На A0 осциллографом проверить оба RESET, нули на PB3–PB6,
   время до настройки UART и неактивность всех CS.
3. Убедиться, что A1 возвращает `A1 00 00 01 02 03 04 05 06 07 08 09 0A 0B`.
4. Через A2 выбрать один слейв; проверить только один активный CS и SWAP:
   передача мастера идёт на PB3 для первой группы или PB5 для второй.
5. Через A4 запросить ID и хэш. При отсутствующем слейве A2 всё равно
   успешен для ID 0–11, а A4 не получает ответа и завершается таймаутом ПК.
6. Прошить слейва, проверить все сообщения прогресса, MAC и отсутствие
   ошибки/переполнения FIFO. Повторить на обеих группах.
7. Проверить переключение A2 без A3, неверный ID и повторный A3.
8. После A3 проверить обычные команды мастера и запуск приложения.

Область приложения и генератор обновления описаны в конфигурации проекта
и README тестового приложения. В образе 16 байт хэша исходного бинарника располагаются
непосредственно перед MAC и включены в расчёт целостности.
