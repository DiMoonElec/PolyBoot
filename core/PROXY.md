# PolyBoot Proxy V1

Прокси включается определением `BOOTLOADER_USE_PROXY` в конфигурации проекта.
В сборку добавляются `core/src/bootloader_proxy.c` и реализация функций
`core/inc/bootloader_proxy_port.h` из проекта мастера. Без define ядро
не вызывает порт прокси; обычные демо не требуют новых файлов или функций.

## Разделение кода

- `bootloader.c`: активация, приём запросов ПК, отправка ответов модуля.
- `bootloader_proxy.c`: команды A0–A4, периодические ответы, порционная
  выдача списка, второй экземпляр Binex и пересылка payload.
- Порт проекта: обнаружение слейвов, RESET/CS, паузы переключения, UART,
  кольцевые буферы и освобождение настроенной периферии.

Динамической памяти нет. При включённом прокси размер буфера приёма ПК
увеличивается с 256 до 512 байт. Модуль содержит отдельные статические
буферы запроса слейву, приёма от слейва и ответа ПК. Внутренний payload
ограничен 511 байтами, ответ с префиксом A4 — 512 байтами.

Модуль обслуживается из `ProcessBootloader()`. Все функции порта begin/poll
неблокирующие. begin начинает новую операцию, poll выполняет короткий шаг
и возвращает BUSY, DONE или ERROR. Итоговый результат сохраняется до
следующего begin. Последовательность аппаратных действий задаёт проект.

## Команды

Все команды доступны после активации мастера. Неверная длина запроса
игнорируется. Обычные команды загрузчика остаются доступны при открытом
прокси-канале; сам по себе A2 не переключает весь поток ПК на слейва.

| Запрос | Ответы |
| --- | --- |
| `A0` | `A0 FF` каждые 200 мс при BUSY, затем `A0 00` либо `A0 01` |
| `A1` | `A1 FF [ID...]` для продолжения, `A1 00 [ID...]` для последней порции; `A1 01` при ошибке |
| `A2 ID` | `A2 00` после готовности выбранного слейва, иначе `A2 01` |
| `A3` | `A3 00` после закрытия, иначе `A3 01` |
| `A4 [payload]` | Для каждого ответа слейва: `A4 [исходный payload ответа]` |

A0 освобождает прежний канал и запускает повторную подготовку/обнаружение.
A1 и A2 до успешного A0 возвращают ошибку. A2 самостоятельно переключает
прежнего слейва на нового; при ошибке порт оставляет канал закрытым.
A3 допустима до A0, при открытом и уже закрытом канале, а также для отмены
незавершённой операции. Закрытие не сбрасывает ядро загрузчика слейва.

Запросы ПК выполняются последовательно: следующий управляющий запрос
отправляется после окончательного ответа. Исключение — A3 для отмены.
OPEN и CLOSE не имеют промежуточных ответов; их время должно укладываться
в таймаут ПК. Только INIT имеет периодические сообщения keep-alive.

## Перечисление слейвов

`port_proxy_get_slave_list(offset, ids, capacity, count)` возвращает порцию
списка, подготовленного при INIT. offset — номер элемента, не числовой ID.
Порт записывает не более capacity идентификаторов и задаёт count.
MORE требует count > 0; DONE допускает count = 0, в том числе пустой список.
Модуль сам передаёт порции и увеличивает offset на count.

Известный список можно выдавать из константного массива, обнаруженный —
из таблицы или битовой маски. Копия полного списка в ядре не нужна.
Список остаётся стабильным до следующего INIT. ID занимают один байт,
допустимы все значения 0..255, поэтому максимум — 256 разных слейвов.
Смещение и количество элементов имеют тип uint16_t; 0xFF не является
признаком отсутствия выбранного слейва.

## Передача A4

Мастер снимает внешний Binex, отправляет внутренний payload обычным
Binex-пакетом слейву и оборачивает каждый принятый payload в A4 для ПК.
Внутри A4 нет вложенного транспортного кадра и нет собственного STATUS.
Модуль не разбирает внутренние команды и статусы, не определяет по ним
окончание операции и пересылает все сообщения прогресса стирания.

При закрытом канале A4 не получает ответа. При повреждённом/потерянном
кадре ответ об ошибке прокси не придумывается: ПК получает таймаут и может
закрыть или открыть канал заново. Автоматических повторов передачи нет.

Полученный ответ не меняется до завершения его передачи в поток ПК.
Прокси-ответы отправляются без BOOTLOADER_RESPONSE_DELAY_MS. Состояние
приёмника ПК сохраняется при отправке асинхронного ответа слейва.

## Скорость и буферизация — ответственность проекта

Общий модуль не ограничивает скорость слейва, не отбрасывает события
и не содержит универсальной очереди. Пока ответ передаётся ПК, модуль
может не читать FIFO слейва. Длительные обычные команды мастера, например
расчёт MAC, также увеличивают время, на которое нужен запас буфера.

Проект обязан обеспечить сохранение входного потока. Возможные решения:
рассчитанный на весь максимальный поток кольцевой буфер, согласованные
скорости или управление выдачей событий в конкретной реализации слейва.

Для расчёта учитывать число сообщений, payload, длину и CRC Binex,
экранирование (каждый байт после START может удваиваться), итоговый ответ,
другие возможные сообщения и задержку обслуживания. Размер очереди
нельзя выбирать только по размеру одного пакета. Переполнение должно
фиксироваться портом; выдавать повреждённый поток за успешный обмен нельзя.
Нужна аппаратная проверка наиболее длинной серии ответов.

Большой FIFO не спасает от потери байта в UART при запрещённых прерываниях.
Запись мастера и обмен со слейвами следует выполнять последовательно,
как предполагает сценарий комплексного обновления.

## Переход к приложению

Перед общим deinit ядро вызывает `port_proxy_deinit()`. Он должен отключить
свой UART/IRQ, очистить pending, освободить CS и все настроенные ресурсы.
Вызов допустим и без предшествующего A0. Не сбрасывать общую GPIO-периферию
во время обычного CLOSE, если ей пользуется интерфейс связи с ПК.

## Проверка на плате

1. До ACTIVATE проверить отсутствие ответов на A0–A4.
2. Проверить быстрый INIT, длительный INIT с промежутками между FF менее
   таймаута ПК, повторный INIT и ошибку аппаратной подготовки.
3. Проверить пустой список, обычный список и выдачу несколькими порциями.
4. Проверить A2 без A0, неверный ID, повторный A2, переключение и ID 255.
5. Проверить A3 до A0, после открытия и повторное закрытие.
6. Через A4 запросить ID/хэш слейва, записать образ и получить ВСЕ
   сообщения прогресса, окончательный ответ и результат проверки MAC.
7. Проверить байты F4/F5, таймаут при отключённом слейве и восстановление
   после закрытия/повторного открытия. Проверить флаг переполнения порта.
8. После A3 проверить обычные команды мастера и запуск его приложения.
